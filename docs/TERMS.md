# 용어 정리 (TERMS)

이 저장소의 한국어 문서·보고서는 **한국 IT 현장에서 통용되는 말**로 쓴다.
영어를 소리나는 대로 옮긴 말(직역어)은 뜻을 바로 알기 어려워 쓰지 않는다.

## 0. 세 가지 원칙

1. **본문은 표준 용어로 쓴다.** 아래 표의 "쓰지 않는 말"은 문서·CLI 메시지·보고서 문구에 쓰지 않는다.
2. **명령어·플래그·JSON 키·파일 이름은 코드 표기(백틱)로 그대로 적는다.** `refine`, `lift`, `shadow` 같은 이름은 바꾸지 않는다.
   다만 본문에서 그 뜻을 말할 때는 한국어 이름을 쓴다(예: `lift` 전환 판정).
3. **전문용어는 처음 나올 때 한 번만 짧게 설명한다.** 독자가 개발자가 아닐 수도 있다(담당자·감독관·평가자).

점검: `go test ./cmd/go-anything -run TestTerminology` 가 한국어가 든 문서·소스 줄을 검사한다.
이 파일과 `WORK/`, `docs/task-id/`는 검사 대상이 아니다.
기계 검사가 막는 것은 1·2절 표의 단어 대부분이다. 다른 뜻이 있어서 사람이 판단해야 하는 단어는 기계 검사에서 뺐다 — 머지(나머지의 일부), 슬라이스(Go slice), 되묻다.

## 1. 바꿔 쓰는 말 (핵심)

| 쓰지 않는 말 | 표준 용어 | 뜻 |
|---|---|---|
| 발산 | **불일치** | 원본과 재작성이 같은 요청에 다르게 답함 |
| 수렴 | **일치 완료** | 서로 다른 시드로 2라운드 연속 불일치 0. "수렴 판정" → "일치 완료 판정" |
| 미수렴 | **불일치 잔존**(아직 미완료) | 라운드가 끝나도 불일치가 남음 |
| 깨끗한 회차, 클린 회차 | **불일치 0 라운드** | 그 라운드에 불일치·차단할 권한 결함이 없음 |
| 회차 | **라운드** | 반복 수정을 한 바퀴 돈 횟수 (하나로 통일) |
| 프로브, 프로빙, 탐침 | **점검 요청**, 점검 | 반복 수정 단계에서 도구가 자동으로 만들어 보내는 시험 요청 |
| 불확실 | **판정 보류** | 그 라운드에 차이의 원인을 판정할 수 없음. 기록에만 남기고 다음 라운드에 다시 본다 |
| 트레이스, 트레이스백 | **호출 스택** | 프로그램이 죽으며 출력하는 오류 경로 |
| 연속 요청 점검 | (추가 기능) | 만들기→조회→수정→삭제처럼 상태를 이어가며 검증 (`POST→GET→PUT→DELETE`) |
| 오라클, oracle | **원본** | 옮기기 전 프로그램. 응답의 정답 기준이 되는 쪽 |
| 녹화 | **기록** | 원본의 입출력을 저장하는 일 |
| 장부 | **기록**(로그) | 라운드별 결과 파일. "라운드 장부" → "라운드별 실행 기록" |
| 심판 | **판정** | 재작성이 맞는지 결정하는 일 |
| 폴백 | **대체 처리** | 정해진 처리가 없을 때 미리 정한 값으로 처리 |
| 스캐폴드, scaffold | **골격 생성** | 실행 가능한 기본 구조를 자동으로 만듦 |
| 리파인, refine | **반복 수정** | 불일치를 0으로 줄이는 자동 반복 단계 (명령은 `refine`) |
| 드리프트 | **변동** | 기록과 지금 응답이 달라지는 현상 |
| 언스테이블 | **비결정 필드** | 실행마다 값이 달라져 비교에서 빼는 필드 (JSON 키는 `unstable`) |
| 확인 안 됨 | **미확인** | 시험하지 못한 범위. 판정의 일부로 그대로 적는다 |
| 웨이브 | **이식 순서**(단계) | 분석 결과로 정한 옮기는 차례 |
| 몽키패치 | **런타임 패치** | 실행 중인 프로그램의 함수를 바꿔치기하는 기법 |
| 프런트 도어 | **진입 프록시** | 요청을 원본 또는 재작성으로 나누어 주는 진입점 |
| 리프트, lift | **전환 판정** | 재작성이 원본을 대체할 준비가 됐는지 판정 (명령은 `lift`) |
| 하니스 | **실행 도구** | 프로그램을 빌드·기동·점검하는 도구 모음 |
| 위탁 | **수정 요청** | 재작성 결함을 에이전트에게 고치도록 넘김 |
| 재판정 | **재검증** | 한 번 판정한 건을 다시 검증 |
| 패싱, 페이싱 | **요청 간격 조절** | 원본이 부하로 죽지 않게 요청 사이에 쉬는 시간을 둠 |
| 옵트인 | **선택 사용**(기본 꺼짐) | 옵션을 줘야만 동작 |
| 머지 | **병합** | 작업 분기를 메인 브랜치에 합침 |

## 3. 도구 명령과 한국어 이름

| 명령 | 한국어 이름 | 하는 일 |
|---|---|---|
| `record` / `verify` | 기록 / 검증 | 명령행 프로그램의 입출력을 기록하고 재작성을 검증 |
| `app record` / `app replay` | 서비스 기록 / 재실행 검증 | HTTP 서비스 전체를 기록하고 다시 보내 비교 |
| `wire gen` | 유닛 부착·골격 생성 | 재작성 유닛을 만들고 `main.go`에 연결 |
| `wire refine` | 반복 수정 | 자동 점검 요청으로 재작성을 검증하고 수정 요청 |
| `rbac` | 권한 검사 | 여러 사용자 자격으로 요청해 허용·거부를 정책과 비교 |
| `secure` | 보안 확인서 검사 | 보안기능 확인서 체크리스트를 코드로 대조 |
| `gate` | 게이트 | gofmt·vet·build·test 등 통과 조건 점검 |
| `analyze` | 이식 순서 분석 | 원본 소스를 분석해 옮길 차례를 정함 |
| `lift` | 전환 판정 | 재작성이 원본을 대체할 준비가 됐는지 판정 |
| `shadow` | 나란히 실행 | 원본·재작성을 같이 돌려 차이를 기록 |
| `bench` / `fuzz` | 성능 비교 / 이상 입력 시험 | 걸린 시간 비교 / 예상 밖의 입력으로 시험 |
| `map` / `profile` / `doctor` | 기록 지도 / 성능 분석 / 진단 | |

## 4. 그대로 쓰는 말

한국 IT 현장에서 널리 통용되므로 그대로 쓴다. 처음 나올 때만 뜻을 덧붙인다.

- **원본 / 재작성**: 옮기기 전 프로그램 / Go로 다시 만든 프로그램
- **기록 / 명세**: 원본의 실제 입출력을 적은 것 / 구현의 근거가 되는 규정
- **유닛(unit)**: 재작성의 단위가 되는 함수 하나 또는 경로 묶음 하나
- **주체(principal)**: 요청을 보내는 사용자 자격 (역할·테넌트)
- **케이스 / 시드 / 라운드**: 시험 입력 하나 / 무작위 값의 기준 숫자 / 반복 수정 한 바퀴
- **게이트**: 통과해야 다음 단계로 갈 수 있는 검증 조건
- **마스킹**: 비교 전에 시각·UUID 같은 값을 고정값으로 바꾸는 것
- **결함 / 원본 결함 / 결함 정책**: 프로그램의 잘못 / 재작성이 아니라 원본에 있는 잘못 / 원본이 죽었을 때 처리하는 방침
- **과적합**: 기록된 입력만 맞추고 다른 입력은 틀리는 구현 (암기)
- **클린룸**: 원본 소스 코드를 보지 않고 기록만으로 구현하는 방식
- **퍼징(fuzz)**: 예상 밖의 입력을 넣어 보는 시험
- **섀도(shadow)**: 실제 요청을 원본이 처리하는 동안 재작성에도 같은 요청을 보내 비교만 하는 방식
- **이관 / 이식**: 프로그램을 다른 언어로 옮기는 일
- **병합 / 커밋 / 빌드 / 배포**: Git·빌드 용어 그대로
- **비결정적**: 같은 요청인데 실행마다 결과가 달라지는 성질
