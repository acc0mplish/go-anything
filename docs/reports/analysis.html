How to read this읽는 법

Readiness준비도 starts at 100 and loses fixed points for each reason found in the package.100에서 시작하여 패키지에서 발견된 이유마다 정해진 점수를 깎습니다. Each reason counts once, however many places cause it. It is a heuristic to order the work, not a measure of effort.하나의 이유는 몇 군데서 나오든 한 번만 계산됩니다. 작업 순서를 정하는 휴리스틱이지 노력의 척도가 아닙니다.

  • unsafe or cgo: -25
  • no tests of its own: -20
  • external side effects (os/exec, net, net/http, net/rpc, database/sql, plugin): -10
  • goroutines: -10
  • wide API (more than 20 exported functions): -10
  • reflection: -5
  • global mutable state: -5
  • init functions: -5

Wave웨이브 is the depth in the import graph inside the module. Wave 0 imports no other package of the module. A package in wave N imports at least one package of wave N-1 and none of a later wave, so porting wave by wave always has its dependencies done.는 모듈 안 임포트 그래프에서의 깊이입니다. 웨이브 0은 모듈의 다른 패키지를 임포트하지 않습니다. 웨이브 N의 패키지는 최소한 웨이브 N-1의 패키지 하나를 임포트하고 더 늦은 웨이브는 임포트하지 않으므로, 웨이브별 포팅은 의존성이 항상 먼저 끝나 있습니다.

Dynamic calls.동적 호출. Call edges come from a static walk of function bodies. Calls through an interface method or a function value cannot be resolved that way; they are counted as dynamic calls and are not edges. The share on the card is dynamic calls over static edges plus dynamic calls; edges count distinct caller and callee pairs while dynamic calls count call sites, so it is a rough indicator.호출 간선은 함수 본문을 정적으로 훑어 나옵니다. 인터페이스 메서드나 함수 값을 통한 호출은 그렇게 해결할 수 없어 동적 호출로 세이며 간선이 아닙니다. 카드의 비율은 동적 호출을 정적 간선과 동적 호출의 합으로 나눈 것으로, 간선은 서로 다른 호출자-피호출자 쌍을 세고 동적 호출은 호출 지점을 세므로 대략적인 지표입니다.

Tests are not walked.테스트는 훑지 않습니다. Only non-test files are read, so calls made from tests do not count as callers, and a package's own _test.go files only decide the "no tests of its own" reason.테스트가 아닌 파일만 읽으므로, 테스트에서 하는 호출은 호출자로 세지 않고, 패키지 자신의 _test.go 파일은 "자체 테스트 없음" 이유만 결정합니다.
