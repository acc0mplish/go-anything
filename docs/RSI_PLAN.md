# RSI 루프 계획: 원본 결함을 찾고 재작성을 굳히는 반복

이 문서는 `wire refine`을 반복 실행해 재작성을 원본과 맞추는 절차를 정한다. 목표는 두 가지다. 재작성이 원본과 다른 곳을 빨리 찾는 것, 그리고 원본 자체의 결함을 기록으로 고정하지 않고 보고하는 것이다.

## 한 라운드의 순서

1. 시드를 정하고 점검 요청을 만든다. 점검 요청은 값 클래스와 인코딩 변형을 포함한다.
2. 원본과 재작성에 같은 요청을 보내고 답을 비교한다.
3. 차이를 셋 중 하나로 분류한다. 원본 크래시는 원본 결함이다. 재작성만 실패한 것은 재작성 결함이다. 판단이 안 서면 사람에게 넘긴다.
4. 재작성 결함만 에이전트에게 고치게 한다. 에이전트에는 기록된 행동만 준다. 원본 소스는 주지 않는다.
5. 불일치 0 라운드를 센다. 차이가 0이고 새 케이스가 없고 권한 치명 결함이 없어야 불일치 0 라운드다.
6. 연속으로 불일치 0 라운드가 두 번 나오면 일치 완료다. 일치 완료에 이르지 못하면 라운드 수 한도에서 멈추고 남은 차이를 보고한다.
7. 일치 완료 뒤에는 점검 요청 밖 입력으로 라이브 교차 검증을 한다.

## 현재 상태 (이 문서 작성 시점)

| 항목 | 상태 | 근거 |
|---|---|---|
| 일치 완료 규칙 (연속 불일치 0 라운드 2개) | 구현됨 | CLI 쌍에서 1라운드 streak 1, 2라운드 일치 완료 확인 |
| 원시 퍼센트 인코딩 점검 요청 | 구현됨 | 기본 실행 HTTP 점검 요청 80에서 121로 증가 (테스트로 확인) |
| 원본 결함 정책 설정 파일 | 구현됨 | `.go-anything/config.json`, 우선순위 테스트 |
| RBAC 게이트 | 구현됨 | 치명 결함이면 일치 완료 차단 |
| 작성자 전용 규칙 (`allowed_principals`) | 구현됨 | 오타 이름 거부 테스트 |
| `expected` 정책의 종료 코드 전용 비교 | 부분 구현 | refine 비교와 기록은 종료 코드(HTTP는 상태)와 stdout만 본다. 크래시 케이스에 `unstable: ["stderr"]`(HTTP는 `"body"`)를 붙인다. 실제 바이너리로 확인했다. 남은 일: `wire gen`이 만드는 `cases_test.go`(usecase/rewritegen.go)가 `unstable`을 무시해 stderr를 그대로 비교한다. 그래서 `-agent` 경로는 아직 호출 스택 출력을 요구한다 |
| 크래시 본문 마스킹 | 구현됨 | 절대 경로는 파일 이름으로, 홈 디렉터리는 `~`로 바꾸고 2048바이트로 자른다. 예외 줄은 잘리지 않는다. 결함 파일과 `expected` 기록 모두 적용한다. 줄 번호는 남긴다 (결함을 알아보는 데 필요하다). 표 테스트: Python, Go 패닉, Node |
| 요청 형태 변형 (HTTP) | 구현됨 | 라운드마다 값 3개에 `?x=1`, 중복 슬래시, 후행 점, 소문자 `get`을 붙인다. 라운드당 최대 12요청이다. `-probes`는 그대로 값 개수다. 로그와 `shape_requests`에 개수가 남는다. Python 원본에서 소문자 메서드 차이(501 대 200)를 실제로 찾았다 |
| 라이브 교차 검증 자동화 | 구현됨 | `-extra-inputs FILE`. 일치 완료 뒤 한 번 양쪽에 보낸다. 차이는 `extra_checked`, `extra_disagreements`로 마지막 라운드 기록과 HTML 페이지에 남고 실행은 실패한다. 원본 크래시는 결함 파일로 간다 |
| 상대 경로 루트 버그 | 고침 | `wire refine conv greet`가 점검 요청 바이너리를 `conv/conv/...`에 만들고 못 찾았다. `Refine` 입구에서 루트를 절대 경로로 바꾼다 |

## 다음 라운드 후보 (우선순위 순)

1. **`expected` 정책을 종료 코드 기준으로 비교.** 원본 크래시가 기대 동작이 되도록 허용하면서, 재작성이 같은 종료 코드를 내면 통과하게 한다. 운영자가 정하는 정책이므로 기본값은 바꾸지 않는다.
2. **크래시 본문 마스킹.** 원본 호출 스택 출력에서 파일 경로와 줄 번호를 지운 뒤에만 기록한다.
3. **요청 형태 변형.** 쿼리 문자열, 후행 점, 중복 슬래시, 대소문자가 다른 메서드를 점검 요청에 추가한다.
4. **라이브 교차 검증 자동화.** 점검 요청 밖 입력 목록을 파일로 받아 일치 완료 뒤 자동으로 비교하고 결과를 라운드 기록에 남긴다.

## 루프를 멈추는 조건

- 일치 완료: 연속 불일치 0 라운드 2개.
- 한도 도달: `-rounds`를 다 쓰면 남은 차이를 보고하고 실패로 끝낸다.
- 분류 불가: 원본과 재작성 중 어느 쪽이 맞는지 기록만으로 정해지지 않으면 사람에게 넘긴다. 이 경우 루프는 기록을 바꾸지 않는다.

## 이 문서가 주장하지 않는 것

- 일치 완료는 샘플링된 점검 요청 안에서의 일치다. 정확성을 증명하지 않는다.
- 원본이 맞는지는 도구가 판단하지 않는다. 원본 결함 정책은 운영자가 정한다.
- 시간, 난수, 요청 간 상태, 동시 요청은 점검 요청이 다루지 않는다.
